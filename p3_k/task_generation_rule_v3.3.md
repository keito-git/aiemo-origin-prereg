# P3-K v3.3 課題の生成規則（2026-11-27 固定。資格試験の前に変えない）

根拠：外部査読5・6（`00_研究計画/20_…`、`23_…`）。この規則で 48 課題を一括で作る。資格試験（J と CTRL だけの順伝播）は各課題に 1 回だけ行い、通らない課題は修正せず除外する。モデルを使った試し（順伝播・生成）は、資格試験の前に一切行わない。

## 1. 課題の数と割り当て

- 48 課題：価値を帯びた課題（V）24、帯びない課題（N）24。番号は V17〜V40、N13〜N36（開発用の V1〜V16・N1〜N12 と重ならない）。
- 6 領域 × （V 4 ＋ N 4）。

| 領域 | V の番号 | N の番号 |
|---|---|---|
| D1 社会・法・道徳 | V17–V20 | N13–N16 |
| D2 健康・安全 | V21–V24 | N17–N20 |
| D3 経済・仕事 | V25–V28 | N21–N24 |
| D4 知識・情報・文章 | V29–V32 | N25–N28 |
| D5 物理・自然 | V33–V36 | N29–N32 |
| D6 技術・工学 | V37–V40 | N33–N36 |

- **V**：判断が評価や規範を含む（良い・悪い・ふさわしい・べき・公正・危険の大きさなど）。
- **N**：評価を含まない記述的な推定（量・時間・距離・頻度・確率・大きさなど）。「良い／悪い」で答えられる問いにしない。
- 開発用の 28 課題と同じ判断（同じ問い、同じ構成概念）は使わない。

## 2. 各課題の中身（Python の辞書。開発用の `p3k_items_v.py` と同じ形に、対照の欄を加える）

```python
TASKS["V17"] = dict(
    name="...", factor="the manipulated factor", domain="D1",
    J=("low anchor", "high anchor", "question ending with ?"),          # 1-9 rating; strong version = higher
    JR=("low anchor", "high anchor", "reverse-keyed question ending with ?"),  # strong version = LOWER
    CAT=("question", ["rank 1 (lowest)", "rank 2", "rank 3", "rank 4 (highest)"]),
    PAIR_Q="Which ... fits better?",
    ctrl="NAME" or "CODE", ctrl_role="the noun phrase the placeholder names, e.g. 'the town'",
    items=[ "text with exactly one [strong|weak] slot and exactly one {CTRL} placeholder", ... 40 items ],
)
```

## 3. 場面（items）の規則

1. 1 課題に 40 場面。どの場面も、別の状況を書く（同じ文の使い回しや、数字だけの入れ替えをしない）。
2. 各場面に、強い版と弱い版を分ける `[強い版|弱い版]` の欄がちょうど 1 つある。欄の外の文は 2 版で共有する。
   - 強い版は、J の評定が高くなる側。
   - 欄の中は 15 語以内。2 版の語数はおおむねそろえる。
3. 強さの程度：強い版も弱い版も、日常的にありうる範囲にとどめる。強い版だけを極端にしない。
   - 一般的な大きさの軸を人工的に強めないため（外部査読5 #2）。
   - 目安は、弱い版が CAT の段階 1〜2、強い版が段階 3〜4 に入る程度。
4. 対照の置き字 `{CTRL}` を、欄の外にちょうど 1 つ置く。
   - NAME：固有名（町・会社・船・通りなど、`ctrl_role` で決めた 1 種類）の位置。
   - CODE：参照番号の位置（例：`file number {CTRL}`）。
   - 置き字の値は、組み立てのスクリプトが乱数種で割り当てる。作り手は値を書かない。
   - 文の内容は、対照の値によって意味が変わらないように書く。
5. 感情語を使わない（開発用と同じ語彙表で自動検査する）。拒否・同意を表す語を、選択肢に使わない。
6. 実在の人物・団体・事件を書かない。

## 4. 対照の生成（設計の上で J と独立にする）

- 課題ごとに対照の種類を 1 つ決める。
  - NAME と CODE を各領域の V と N で半々にする。
  - 割り当ては乱数種 20261227 で決める。作り手は割り当てに従う。
- **NAME**
  - 値は名前の文字数。4 区分：3〜4 文字、5〜6、7〜9、10〜12。
  - 40 場面に各区分 10 ずつを、乱数種で並べ替えて割り当てる。
  - 名前は、意味を持たない作り語（子音と母音の音節の組み合わせ）を、乱数種で区分の文字数に合わせて作る。英単語や感情語と一致するものは除く。
  - 問い
    - CTRL：「how many letters are in the name of {ctrl_role}?」
    - CTRL_CAT：選択肢は「three or four letters」「five or six letters」「seven to nine letters」「ten or more letters」。
- **CODE**
  - 値は参照番号の桁数。4 区分：2〜3 桁、4〜5、6〜7、8〜9。
  - 割り当ては NAME と同じ。数字は乱数種で作り、先頭は 0 にしない。
  - 問い
    - CTRL：「how many digits does the reference number have?」
    - CTRL_CAT：選択肢は「two or three digits」「four or five digits」「six or seven digits」「eight or nine digits」。
- 強い版と弱い版は、同じ対照の値を共有する。
- 対照の値は、場面の内容とも強弱とも独立に決まる。

## 5. 読み出し（段階 D で凍結した手順）

- J・JR・CTRL：1〜9 評定（開発用と同じ文型）。
- CAT・CTRL_CAT：4 択、巡回の 4 回転（開発用と同じ）。
- PAIR：段階 13・24・14 の 2 択、両順（D2）。
- 写像：1（A B C D）、2（Q X Z J）、K-a（H K R W）、K-b（G N P T）、3（ψ ξ ζ θ）。各写像で、ラテン方格の組を課題ごとに釣り合いをとって割り当てる（開発用と同じ方法）。

## 6. 資格用の場面と本番の場面

- 40 場面のうち 10 を資格用、30 を本番用にする。分け方は乱数種 20261228 で決める（作り手は知らない）。
- **資格試験**
  - 資格用の 10 対で、J と CTRL だけを計算する。
  - 通る条件：J の効果（強い版 − 弱い版の平均）> 1、かつ |ρ(CTRL の得点, J の得点)| < .3。
  - JR・選択の読み出し・勾配・操舵は使わない。
- 資格試験は 1 回だけ行う。通らない課題は除外する（修正しない）。
- 本番は、通った課題の本番用 30 対だけを使う。

## 7. 作った後の自動検査（モデルを使わない。違反は文面を直してよい）

- 形式：40 場面、欄 1 つ、置き字 1 つ、欄の語数、選択肢 4 つ。
- 重複：場面の重複。開発用 28 課題との 6-gram の重なり。課題間の 6-gram の重なり。
- 語彙：感情語、拒否語。
- 対照：区分の釣り合い（各 10）。

この検査はモデルの反応を見ないので、違反を直すことは「モデルに合わせた最適化」にあたらない。直した箇所は記録する。
